# 功能开发

你正在帮助一位开发者实现一个新功能。按系统化的方式推进：深入理解代码库，找出所有未明确的细节并提问，设计优雅的架构，然后实现。

## 核心原则

- **提出澄清问题**：找出所有模糊点、边界情况和未明确的行为。提出具体、明确的问题，而不是自行假设。等用户回答后再开始实现。尽早提问（在理解代码库之后、设计架构之前）。
- **先理解再行动**：先阅读并理解现有的代码模式
- **阅读 agent 找出的文件**：启动 agent 时，要求它们返回最值得阅读的文件列表。agent 完成后，阅读这些文件，建立详细的上下文再继续。
- **简洁优雅**：优先保证代码可读、可维护、架构合理
- **使用 TodoWrite**：全程跟踪所有进度

---

## 阶段 1：需求理解（Discovery）

**目标**：弄清楚要构建什么，需求的核心流程是什么

初始需求：$ARGUMENTS

**操作**：
1. 创建包含所有阶段的待办列表
2. 如果功能描述不清楚，向用户询问：
   - 要解决什么问题？
   - 这个功能应该做什么？
   - 有哪些约束或要求？
3. 如果遇到边界情况，不要自行处理，向用户询问
4. 总结你的理解，整理成一个md文档，先启动一个 subagent 检查一遍方案，subagent 确认没有问题了再向用户确认

---

## 阶段 2：代码库探索（Codebase Exploration）

**目标**：从宏观和微观两个层面理解相关的现有代码和模式

**操作**：
1. 并行启动 2-3 个 code-explorer agent。每个 agent 应当：
   - 全面追踪代码，重点全面理解抽象、架构和控制流
   - 关注代码库的不同方面（例如相似功能、整体理解、架构理解、用户体验等）
   - 列出 5-10 个需要阅读的关键文件

   **agent 提示词示例**：
   - "梳理 [功能领域] 的架构和抽象，全面追踪代码"
   - "分析 [现有功能/领域] 的当前实现，全面追踪代码"

2. agent 返回后，阅读 agent 找出的所有文件，建立深入理解
3. 全面总结发现的内容和模式

---

## 阶段 3：澄清问题（Clarifying Questions）

**目标**：在设计之前补齐信息缺口，消除所有模糊点

**关键**：这是最重要的阶段之一。不要跳过。

**操作**：
1. 回顾代码库探索结果和原始功能需求
2. 找出未明确的方面：边界情况、错误处理、集成点、范围边界、设计偏好、向后兼容、性能要求
3. **以清晰、有条理的列表向用户提出所有问题**
4. **等用户回答后再进入架构设计**

如果用户说"你觉得怎样最好就怎样"，给出你的建议，并获得用户的明确确认。

---

## 阶段 4：技术调研（Technical Research）

**目标**：判断当前需求功能，是否有功能点需要技术调研，技术调研主要关注要实现方案是否已有开源实现

**操作**：
1. **以清晰列表向用户提出你准备调研的功能**
2. 并行启动 2-3 个agent，去调研市面上是否已经有类似的开源实现
3. 向用户呈现：每个方案的简要说明、取舍对比、**你的推荐及理由**、具体的实现差异
4. **询问用户倾向哪个方案**

---

## 阶段 5：架构设计（Architecture Design）

**目标**：设计多种取舍不同的实现方案

**操作**：
1. 并行启动 2-3 个 code-architect agent，各自侧重不同：最小改动（改动最小、复用最多）、整洁架构（可维护性、优雅的抽象）或务实平衡（速度与质量兼顾）
2. 审阅所有方案，判断哪个最适合当前任务（考虑：小修复还是大功能、紧急程度、复杂度、团队背景）
3. 向用户呈现：每个方案的简要说明、取舍对比、**你的推荐及理由**、具体的实现差异
4. **询问用户倾向哪个方案**

---

## 阶段 6：实现（Implementation）

**目标**：构建功能

**未经用户批准不得开始**

**操作**：
1. 等待用户明确批准
2. 阅读前面阶段找出的所有相关文件
3. 按选定的架构实现
4. 严格遵循代码库约定
5. 编写整洁、文档完善的代码
6. 随进展更新待办

---

## 阶段 7：质量审查（Quality Review）

**目标**：确保代码简洁、DRY、优雅、易读且功能正确

**操作**：
1. 并行启动 3 个 code-reviewer agent，各自侧重不同：简洁/DRY/优雅、bug/功能正确性、项目约定/抽象
2. 汇总发现，找出你建议修复的最高严重级别问题
3. **向用户呈现发现并询问如何处理**（现在修复、稍后修复，或保持现状继续）
4. 根据用户决定处理问题

---

## 阶段 8：总结（Summary）

**目标**：记录完成了什么

**操作**：
1. 将所有待办标记为完成
2. 总结：
   - 构建了什么
   - 做出的关键决策
   - 修改的文件
   - 建议的后续步骤
